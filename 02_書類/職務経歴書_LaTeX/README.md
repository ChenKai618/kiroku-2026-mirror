## 2つの組版

| ファイル | 組版 | 特徴 |
|---|---|---|
| `build.tex`（旧・従来版） | Verbatim（等幅・左寄せ固定） | テキストをそのまま流し込む。右側に空白が出る |
| `build_jlreq.tex`（新・通常組版） | jlreq 段落・両端揃え | 右空きがなく日本語らしい見た目。**テクニカルスキルに言語使用年数を追記済み** |

**新規追加・修正は `build_jlreq.tex` を直接編集する。** 内容は .txt とほぼ同一だが、
構造（見出し・箇条書き）は LaTeX で書かれている。

## 再ビルド手順（build_jlreq.tex）

```bash
cd 職務経歴書_LaTeX
docker run --rm -v "$PWD":/workdir paperist/texlive-ja:latest latexmk -lualatex build_jlreq.tex
```

（旧 build.tex の再ビルドは下記の従来手順）

## 再ビルド手順

本文（.txt）を編集したあと：

```bash
cd /tmp/shokumu
python3 -c "
import io
body = io.open('$HOME/Desktop/Github/Tensyouku/02_書類/職務経歴書_陳凱_20260829.txt', encoding='utf-8').read()
esc = body.replace(chr(92), r'\textbackslash{}').replace('#', r'\#').replace('&', r'\&').replace('_', r'\_').replace('%', r'\%')
tex = io.open('build.tex', encoding='utf-8').read()
head = tex[:tex.index('commandchars=') + 30]
io.open('s.tex','w',encoding='utf-8').write(head + chr(10) + esc + chr(10) + r'\end{Verbatim}' + chr(10) + r'\end{document}' + chr(10))
"
docker run --rm -v "$PWD":/workdir paperist/texlive-ja:latest latexmk -lualatex s.tex
```

> 💡 **Word / Google Docs で作っても構わない。** 職務経歴書は自由フォーマットであり、
> 組版の美しさではなく中身で評価される。等幅フォントの体裁が好みでなければ、
> `.txt` の内容を Word に貼り付けて PDF 保存するだけでよい。

## この職務経歴書の構成と、そう書いた理由

| セクション | 意図 |
|---|---|
| **職務要約** | 冒頭で「損保・基幹システム・AWS移行・大手SIer元請・12名体制」を出す。ここで読む手が止まる |
| **活かせる経験・スキル** | 検索とスクリーニングで見られる。**日本語での設計書作成**を上位に置いた（在日中国人エンジニアの多くができない差別化点） |
| **テクニカルスキル** | 言語／FW／クラウド／その他で分類。羅列より分類の方が「整理できる人」に見える |
| **職務経歴【1】** | 現職。**顧客名は書かない**（MS&AD／NTTデータ） |
| **職務経歴【2】** | RPA。UI改修を「コードビハインド→ViewModelへの責務移行」として書き、単なる画面調整に見せない |
| **職務経歴【3】** | **義務兵役として明記**。技術内容は具体的に、機関名と監視対象のみ守秘義務で伏せる |
| **その他の開発経験** | 卒業研究。**2023年からWeb開発をしている証拠**として技術線を繋ぐ |
| **個人開発** | 3プロジェクトを簡潔に＋**設計判断3点**。実装力ではなく設計判断で差別化する |
| **自己PR** | 2ブロック。学習速度と、曖昧な情報を判断可能にする力 |

### 書いていないこと（＝盛らなかった部分）

- ❌ 「設計を主導した」→「参加」「作成」に留めた
- ❌ 「AWS環境を構築した」→ 基盤チームの担当であることを明記
- ❌ 「パフォーマンスをX%改善」→ 測っていないので書かない
- ❌ **「200コミット」→ 削除した**（実装の多くはAI併用であり、実装力の証拠にならない）
- ❌ プロジェクト規模の水増し → 12名のまま

**参加した工程を正確に書くのは盛りではなく、標準的な書き方。**

### AI併用を自分から開示している

「実装には生成AIを併用しておりますが、アーキテクチャの選定と設計判断は自身で行い、
その理由と却下した代替案をADRとして文書化しています。」

隠すと面接の深掘りで崩れる。**先に開示すれば、それ自体が誠実さの証拠になる。**
→ [ADR-0006](../../docs/adr/0006-ai-assisted-development-disclosure.md)
