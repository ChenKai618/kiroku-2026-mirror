## ビルド手順

```bash
# 1. クローン
git clone https://github.com/jugesuke/rirekisho.git
cd rirekisho

# 2. このフォルダの main.tex で上書き
cp ~/Desktop/Github/Tensyouku/02_書類/履歴書_LaTeX/main.tex .

# 3. 証明写真を置く（任意・後述）
cp ~/Downloads/photo.jpg .

# 4. ビルド（Docker が必要。OrbStack/Docker Desktop を起動しておく）
npm install
npm run init      # 初回のみ（Dockerイメージのpull）
npm run build     # → out/main.pdf
```

**⚠️ Docker が起動していないとビルドできない。** OrbStack を先に立ち上げること。

### ⚠️ 差し替えを推奨する（急がなくてよい）

**このまま出しても書類選考は通る。だが2つ問題がある：**

1. **髪が整っていない** — 頭頂の毛が数本跳ねている。
   日本の証明写真では「清潔感」が明確に評価される項目。
   ※ 跳ねた毛を消す処理も試したが、**輪郭がギザギザになり修整跡が目立った**ので採用しなかった。
   **本物の欠点は、下手な加工より害が小さい。**
2. **AI生成である** — 面接では本人に会う。
   美肌・輪郭補正が入っていると、写真と実物の差が違和感になる。
   外国人の場合、在留カードの写真と並べて見られる可能性もある。

**写真館で撮り直したら、同じファイル名 `photo.jpg` で置き換えるだけでよい。**

| 方法 | 費用 | 内容 |
|---|---|---|
| 駅前の証明写真機 | 700〜1000円 | 5分。Ki-Re-i 等はスマホにデータを送れる |
| **写真館の就活写真** | **3000〜5000円** | **店員が髪・襟・ネクタイを整えてくれる**。修整込み・データ付き |

**写真館を勧める。** この転職の目標は年収+100〜150万。
全ての応募先が見る1枚に5000円を使うのは、**この計画で最も費用対効果が高い出費**。

撮影前の準備：
- **髪は前日に洗い、当日ワックスで抑える**（前髪が眉にかからない・横が膨らまない）
- 濃紺スーツ + 白シャツ + 無地のネクタイ ← **現在の写真の配色は正しい**
- ネクタイの結び目を襟元まで締め、シャツの第一ボタンを留める
- 表情は笑わなくてよいが、**口角を下げない**。目線はカメラへ
- **3ヶ月以内に撮影したもの**を使うのが原則

## 記載内容の判断（なぜこう書いたか）

### 学歴：専科（2016-2019）を書いていない

本人の指示による。**「2022年9月 入学 → 2024年6月 卒業」だけだと2年で大学を卒業したように見える**が、
これは**編入学（専升本）だから正しい**。

**ただし面接では必ず聞かれる。** そのときはこう答える：

```
「2019年に専門課程を修了後、本国の義務兵役に従事し、
2022年に大学へ編入学いたしました。」
```

BizReach など Web の登録フォームでは「特記事項」欄に
`2019年に専門課程を修了後、本国での義務兵役に従事し、2022年に大学へ編入学` と明記してある。
**履歴書は行数が限られるため省略しているが、隠しているわけではない。**

### 職歴：「中国国内 公的機関」と書いた

**「公的機関」だけだと日本の機関に見える。** 「中国国内」を付けることで、
**日本人が知らない機関名であることに自然な理由が生まれる。**

「隠している」ではなく「海外の機関だから知らなくて当然」という読まれ方になる。

特記事項の「本国での義務兵役」と照らせば、読み手は自分で状況を理解する。
**言わせずに伝わるのが最も強い。**
→ [ADR-0003](../../docs/adr/0003-no-factual-fabrication.md) / [ADR-0011](../../docs/adr/0011-monitoring-project-backs-infra-tags.md)

### 志望の動機欄：会社ごとに書き換える

現在の内容は**汎用版**（現案件 → AWS取得の経緯 → 今後の方向性 → 個人開発）。

**応募先が決まったら、その会社固有の要素を1つ以上入れる。**
使い回しは必ず見抜かれる。→ `05_面接/想定問答集.md` の志望動機テンプレート

### 本人希望記入欄：在留資格を先に書いた

「貴社の規定に従います」だけで終わらせず、**在留資格の期限と更新の必要性を明記**。

隠して後出しすると「段取りができない人」に見える。
ここで引く企業は外国人雇用の経験が薄いので、早く弾かれた方がいい。

## 職務経歴書はこれで作らない

**履歴書と職務経歴書は別物。**

| | 履歴書 | 職務経歴書 |
|---|---|---|
| 形式 | **固定フォーマット**（厚労省様式例） | **自由フォーマット** |
| 内容 | 氏名・住所・学歴・職歴の一覧・資格 | 案件詳細・技術スタック・担当業務・成果 |
| 枚数 | A4 2枚（固定） | A4 2〜3枚 |
| 役割 | 身分と事実の登録（行政手続き的） | **書類選考の合否を決める主武器** |

**日本のIT中途採用で真剣に読まれるのは職務経歴書のほう。**

職務経歴書の内容は `../職務経歴書.md` にある。**ただし自分で組版する前に、
エージェント面談で必ずこう聞くこと：**

```
「職務経歴書のフォーマットはご指定がありますか。
テンプレートがあればいただけますか。」
```

**多くのエージェントは自社テンプレートを持っており、そちらの方が通過率が高い。**
企業側が見慣れた形式だから。内容は既に書いてあるので、貼り付けるだけでよい。

自分で作る場合は **Word / Google Docs → PDF** で十分。**LaTeX は不要。**
職務経歴書は組版の美しさではなく中身で評価される。
