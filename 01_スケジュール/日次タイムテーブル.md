# 一日のタイムテーブル — 現場が暇な時間を武器に変える

> **お前の最大の戦術的資産は「現場に仕事がほとんどない」ことだ。**
> ほとんどの転職者は、忙しい仕事の合間に転職活動をする。お前には1日4〜5時間の可処分時間がある。
> ただし**会社のPCではアカウントにログインできない**——この制約が、実は安全な線引きになる。

---

## 🔴 大原則：会社のPCと自宅のPCで、やることを完全に分ける

```
┌──────────────────────────────────────────────────────────┐
│  会社PC（ログイン不可・ブラウジングのみ）                    │
│  → ログイン不要で、かつエンジニアとして自然な行動だけ         │
│                                                           │
│  自宅PC                                                    │
│  → 転職活動そのもの（応募・エージェント・書類・面接）          │
└──────────────────────────────────────────────────────────┘
```

**この線を越えるな。** 越えた瞬間、契約書第5条（自宅待機・無給）のリスクが現実になる。
現場から外されれば、収入と「MS&AD案件参画中」という最大の武器が同時に消える。

# 🏢 会社時間（9:00-18:00／可処分 約4〜5時間）

## ✅ やっていいこと（ログイン不要・行動として自然）

### ① 自分のADRとコードを読む ★最優先

**`bikuri-NihongoLens` は公開リポジトリだ。github.com をブラウザで開くだけで読める。ログイン不要。**

```
https://github.com/RainYaya/bikuri-NihongoLens/tree/main/docs/adr
```

**これが会社時間で最も価値のある作業だ。** 理由：
- 面接で聞かれる設計質問の答えが、そこに書いてある
- エンジニアがGitHubを見ているのは、**世界で最も自然なブラウジング履歴**
- 転職活動の痕跡が一切残らない

**読む順番**（`04_コード理解/学習方案.md` に詳細）：
```
Day 1-2   ADR 6本を通読（思い出す作業）
Day 3-5   各ADRを「決定・理由・却下案・残る制約」の4点で整理（紙のノートに手書き）
Day 6-10  公開コードを読む（タスクキュー → SSE → WhisperX呼び出し）
```

> 💡 **メモは紙のノートかスマホに。会社PCにファイルを作るな。**

### ② 現場の旧コードを読み込む ★これが唯一の「二重取り」

**これは「仕事」であり、同時に「面接の弾薬」だ。**

お前は「この案件は価値がない」と言った。だが面接で必ず聞かれる質問がある：

> 「このプロジェクトで一番苦労した点は何ですか？」

**旧システムのコードを本気で読み込めば、この答えが本物になる。**

読むべきもの：
- [ ] 旧Javaフレームワークの構造（何というFWか、どういう設計思想か）
- [ ] 画面遷移とセッション管理がどうなっているか
- [ ] Thymeleaf移行で何が難しいか（旧FWのテンプレート機構との差）
- [ ] オンプレ前提の処理でEC2に載らない箇所（ファイルパス、バッチ、ローカル依存）
- [ ] 設計書に書かれていない挙動が実装にどれだけあるか

**この作業は、真面目に働いているようにしか見えない。しかも本当に真面目に働いている。**
そして面接では「レガシー移行の難所を具体的に語れる人」になる。

### ④ 日本語の技術語彙を仕込む

お前は日本語ブログを読んでいると言った。**それを転職向けに寄せろ。**

読むべきもの：日本のエンジニアが書いた**設計・アーキテクチャの記事**。
目的は知識ではなく、**日本語での技術的な言い回しを体に入れること**。

`04_コード理解/学習方案.md` に用語の読み方リスト20語がある。
**「冪等性（べきとうせい）」を面接で読み間違えたら、それまでの印象が全部崩れる。**

### ⑤ 職務経歴書に使う事実を、紙のノートに記録

思い出したときに書き溜める：
- 内部設計書：___本
- 外部設計書：___本

## ③ 日本語音読（30分）★これを飛ばすな

**理由**：お前の武器は発音だ。だが**技術内容を日本語で話した経験がない。**
内容を思い出しながら話すと、発音は必ず崩れる。**暗記して初めて、発音の強さが活きる。**

```
Day 1-7    想定問答 TOP5 を1問ずつ音読（各3回）
Day 8-14   ADR回答6本を音読
Day 15-    紙を見ずに言えるかテスト。詰まったら戻る
```

**必ず声に出せ。** 黙読では口が動かない。面接で動くのは口だ。

### 土曜
```

午後  コード理解の深掘り 2時間（平日30分では届かない部分）

```

### 日曜
```
午前  休み ★完全に転職を忘れる
午後  来週の計画・書類の見直し
夜    休み
```

**週に1日は転職を考えない時間を作れ。** 10週間は長い。

# 🎯 フェーズ別の重点シフト

```
W1     書類 70% / コード理解 30%
       → とにかくエージェント登録まで走る

W2-3   応募 50% / コード理解 50%
       → 書類選考中は技術を聞かれない。この期間にコードを詰める

W4-5   面接準備 60% / コード理解 40%
       → 音読の比重を上げる

W6-7   面接実践 80% / 復習 20%
       → 面接前日は該当プロジェクトのADRを30分復習するだけ

W8-10  交渉 100%
       → 新しい準備はしない。持ち札で戦う
```

---

# 🚨 やってはいけない時間の使い方

| ❌ | なぜ |
|---|---|
| 「準備が完璧になってから応募する」 | **10週間しかない。** 応募しながら準備するのが正しい。書類選考中に技術は聞かれない |
| 新しい技術を勉強し始める | **今から始めたものは面接に間に合わない。** 手持ちの札を磨け |
| 4つ目のAWS資格を取る | もう十分だ。**それより自分のコードを理解しろ** |
| 新しい個人開発を始める | 既存3つを語れる方が100倍価値がある |
| 1日3件以上の面接 | 消耗する。**2件が上限** |
| 落選理由を延々と考える | **7割落ちるのが正常**。次に行け |
