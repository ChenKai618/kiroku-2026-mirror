# 面接PPTの使い方

## 📁 ファイル

`技術ポートフォリオ.html` — ブラウザで開くだけ。8ページ。

```bash
open ~/Desktop/Github/Tensyouku/05_面接/技術ポートフォリオ.html
```

**操作**：`→`/`Space` 次へ ／ `←` 戻る ／ `F` フルスクリーン ／ `G` ページ一覧
**PDF化**：`Cmd+P` → 「背景のグラフィック」をONにして保存

---

## 🔴 最重要：自分から出すな

**日本の中途面接で、候補者が自発的にPPTを開くのは「用力過猛」に見えるリスクがある。**
だがこの資料は**中身がアーキテクチャ図だけ**なので、聞かれた時に出せば加点になる。

### 正しい出し方

面接官が個人開発について聞いてきたら、口頭で1〜2分説明する。
相手が食いついた（「へえ」「もう少し詳しく」等の反応）と感じたら：

```
「よろしければ、構成図をご用意しているので
画面共有でお見せしましょうか」
```

**相手が「お願いします」と言ってから開く。** これが唯一の正解。

### やってはいけないこと

| ❌ NG | 理由 |
|---|---|
| 面接開始直後に「資料を用意しました」 | 圧が強い。相手のペースを奪う |
| 自己紹介をPPTでやる | 中途面接では過剰。新卒みたいに見える |
| キャリアプランのページを入れる | 「意識が高い人」に見えて逆効果 |
| 8ページ全部を順番に説明する | 長い。**相手が聞いた1〜2ページだけ見せる** |
| 対面面接で紙に印刷して配る | オンラインの画面共有ならOKだが、紙は重い |

## 📄 各ページの使いどころ

| # | ページ | いつ見せるか |
|---|---|---|
| 1 | 表紙 | 画面共有の開始時に一瞬だけ |
| 2 | 個人開発の実績 | 「どんなものを作ったか」を聞かれたら |
| 3 | アーキテクチャ | 「技術構成は？」を聞かれたら |
| **4** | **並行制御** | ★**「工夫した点は？」の本命。ここが一番強い** |
| **5** | **単一真相** | ★**「設計で悩んだ点は？」の本命** |
| 6 | BYOK | 「セキュリティは考えた？」を聞かれたら |
| 7 | AIとの向き合い方 | ★**「AIで作ったの？」と聞かれたら** |

**実際の面接では、4番か5番の1ページだけ見せて終わることが多い。それで十分。**

## 🎤 4番（並行制御）を見せながら話す台本

```
「長時間かかるタスクが2種類ありました。
動画のダウンロードと、音声の文字起こしです。

最初は同じキューに入れていたのですが、
文字起こしを並列で走らせるとGPUのメモリを取り合って、
遅くなるだけでなくOOMで落ちることがありました。

そこで、キューの方針を種別ごとに分けました。
文字起こしは直列。GPUが1枚しかないので。
ダウンロードは並列。こちらはネットワーク律速なのでGPUを取り合いません。

つまり『何が競合資源か』でキューを分けた、というのが判断のポイントです。

この判断は、コードを読んでも理由が分からないので、
ADRという形で文書に残しています。
将来並列転録をやりたくなったら、
先にVRAMの隔離を解決する必要がある、という制約も一緒に書いています。」
```

**この台本の強さ**：
- 「最初はこうしていたが、問題が起きて変えた」= **実際に手を動かした証拠**
- 「何が競合資源か」= 抽象化して原則を語れている
- 「コードを読んでも分からない制約を残した」= **設計者の視点**

## 🎤 7番（AI）を見せながら話す台本

これは**攻められた時の防御ではなく、先に出す攻撃**として使える。

```
「実装には生成AIを積極的に使っています。隠すことではないと思っています。

ただ、やってみて分かったのは、
AIを使うほど『何を作るか』『なぜそうするか』を
自分で決めて言語化する必要が出てくるということです。
指示が曖昧だと、動くけれど後で崩れるコードが出てくるので。

なので設計判断はADRとして6本残していて、
決定・理由・却下した代替案・残る制約の4点を書いています。

実務でもAIを前提とした開発になっていくと思いますので、
その使い方を個人開発で練習している、という位置づけです。」
```
