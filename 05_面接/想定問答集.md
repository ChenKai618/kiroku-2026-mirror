# 面接 想定問答集

> **使い方**：一次面接の1週間前から毎日音読。**紙を見ずに言えるまで。**
> お前の武器は発音だ。だが「内容を思い出しながら話す」と発音は崩れる。
> 暗記して初めて、発音の強さが活きる。

---

## 🎯 日本のIT中途面接の構造

| 段階 | 誰が出るか | 何を見るか | 対策の重点 |
|---|---|---|---|
| **カジュアル面談** | 現場エンジニア/人事 | 相互の情報交換（選考ではない） | **練習台として最大活用** |
| **一次面接** | 人事＋現場リーダー | 経歴の整合性・人柄・日本語力 | 転職理由・経歴説明 |
| **二次面接** | 技術責任者・部長 | **技術の深さ** | ★ADR・個人開発 |
| **最終面接** | 役員・事業部長 | 志望度・カルチャーフィット・長期性 | 志望動機・逆質問 |

**技術を深掘りされるのは主に二次。** 一次は「話が通じるか」を見ている。
だから **Week 1のADR読解だけで一次は戦える。**

# 🔥 最重要質問 TOP5（これだけは完璧に）

## Q1「転職理由を教えてください」★最頻出

```
「契約期間の満了が最も大きな理由です。

現在は契約社員として1年ごとの有期契約で就業しており、
2026年11月30日で契約が満了いたします。

現在の案件では、オンプレミスからAWSへの移行という案件で
外部設計から内部設計、テストまで幅広く経験させていただき、
非常に勉強になりました。

一方で、AWS周りはインフラ基盤チームが担当する体制でしたので、
今後は自分でクラウドの設計や構築まで踏み込める環境で
専門性を積み上げていきたいと考えております。

そのため、この契約満了のタイミングで、
正社員として長期的にキャリアを築ける環境を探しております。」
```

**設計意図**：
- 「契約満了」= 反論不能。**短期離職の懸念がここで消える**
- 現職を**褒めてから**次を語る（悪口ゼロ）
- 「AWSに踏み込みたい」= 志望動機に自然に繋がる
- 給与の話は一切していない

**❌ 絶対に言うな**：給料が安い／社長が資格代を出さない／自分より下の人が高給／会社が中国人経営で不透明

## Q2「日本に来てまだ短いですが、大丈夫ですか」

```
「2026年に来日し、現在の現場が初めての日本での実務経験です。

ただ、日本語については日本語能力試験のN1を取得しており、
現場では日本語で外部設計書・内部設計書を作成し、
チーム内のコミュニケーションも日本語で行っております。

日本の開発現場の進め方——設計書をきちんと作ってレビューを通す、
成果物の粒度を揃える、といった文化については、
現在の現場で一通り経験させていただきました。

正直に申し上げますと、日本のビジネス慣習で
まだ知らないことは多いと思っております。
ただ、必要だと分かったことは短期間で身につける自信があります。
実際、現場でAWSの知識が必要だと判断してから、
2ヶ月でCLFからSAPまで取得いたしました。」
```

**設計意図**：
- 弱点を**先に認める**（隠すと突かれる。認めると攻撃が成立しない）
- 「日本語で設計書を作成」= 具体的な証拠
- 最後に**学習速度の実証**で締める。弱点を強みに転換

## Q3「1ヶ月でAWS資格を3つ取ったのはなぜですか」★ここで差がつく

```
「現在参画しているのが、オンプレミスからAWSへの移行案件です。

インフラ基盤チームが別にいてAWS側を担当しているのですが、
開発側の自分も移行先の全体像を理解していないと、
設計上の判断ができない場面が出てきました。

そこで体系的に学ぶ必要があると考えまして、
まず全体像を掴むためにCLF、
次に設計の基礎としてSAA、
さらに移行アーキテクチャの判断軸が欲しくてSAPまで取得しました。

ただ、実務経験としてはまだ浅いと自覚しております。
資格で得たのは知識と共通言語で、
基盤チームと同じ論点で議論できる土台ができた、という段階です。

今後は実際に手を動かして構築する経験を積みたいと考えており、
それが今回の転職理由の一つでもあります。」
```

**設計意図（重要）**：
- 資格取得の動機が**実際のプロジェクトに紐づいている** → 資格コレクターではない
- **「実務経験は浅い」と自分から言う** ← これが最大の防御
- 「資格で得たのは共通言語」= 資格の限界を正しく認識している人に見える
- 最後に志望動機へ接続

> ⚠️ **絶対にやってはいけないこと**：SAPを持っているからと「AWSは得意です」と言うこと。
> 面接官は必ず実務の深さを試しに来る。**先に「浅い」と認めれば、その攻撃は不発になる。**

## Q4「現在の案件について詳しく教えてください」

```
「損害保険会社向けの申込管理システムを、
オンプレミス環境からAWSへ移行するリプレイス案件です。
大手SIerが元請の案件で、私は開発チームに所属しています。

システムは長年オンプレで運用されてきたもので、
かなり古いJavaのフレームワークで構築されていました。
これをThymeleafベースの構成に刷新し、
アプリケーションサーバをAWSのEC2上に移行するという内容です。

チームは12名で、開発チームとは別にインフラ基盤チームがあり、
AWS側の構築は基盤チームが担当しています。

私の担当は、既存システムのソースコード解析と現行仕様の調査から始まり、
外部設計書・内部設計書の作成、
移行方式に関する設計レビューへの参加、
それから単体テストの仕様書作成とテスト実施です。

移行案件なので、既存の挙動を正確に把握することが重要で、
旧コードを読み解いて仕様を復元する作業に一番時間を使いました。」
```

> 💡 **顧客名（MS&AD/三井住友海上/NTTデータ）は絶対に言わない。**
> 「損害保険会社向け」「大手SIer元請」で十分。具体名を言うと**守秘義務の意識がない人**と見られる。
> これは減点であって加点ではない。

### 深掘り対策

| 質問 | 答え方 |
|---|---|
「一番苦労した点は？」 | 「旧システムのドキュメントが十分でなく、コードから仕様を復元する必要があった点です。設計書に書かれていない挙動が実装に残っていて、それが仕様なのか不具合なのかの判断を、有識者に確認しながら進めました」 |
「移行で難しいのはどこ？」 | 「既存の挙動を変えないことと、クラウド前提の構成に合わせることの両立です。オンプレ前提で書かれた処理が、そのままではEC2上で成立しない部分がありました」 |
「AWSは具体的に何を？」 | 「基盤チームがEC2の構築を担当していて、私は開発側です。**構築そのものは経験していません。** ただ移行先の構成を理解する必要があり、そのために資格を取りました。今後は構築側にも踏み込みたいと考えています」 ← **正直に言う。ここで嘘をつくと崩れる** |
「テストは何を？」 | 「単体テストです。旧システムの既存コードに対するUTの仕様書を作成し、実施しました」 |
「チームでの役割は？」 | 「開発メンバーです。設計は先輩と一緒に進めていて、レビューにも参加させていただいています」 ← **「主導した」と言うな。聞かれたら正直に** |

## Q5「個人開発について教えてください」★お前の最大の武器

```
「業務外で継続的に個人開発をしております。
2026年3月以降で4つのプロジェクトを実装し、
うち2件を公開して稼働させています。

一番技術的に踏み込んだのは、日本語学習用のデスクトップアプリです。
字幕のない日本語動画に対して、WhisperXという音声認識モデルで
単語レベルのタイムスタンプ付き字幕を生成して、
動画と字幕とタイムラインを同期させた精読環境を作るものです。

技術的に工夫した点を2つ挙げますと、

1つは並行処理の設計です。
ダウンロードと文字起こしという2種類の長時間タスクがあるのですが、
文字起こしはGPUが1枚しかないので直列に、
ダウンロードはネットワーク律速なので並列に、
とキューの方針を分けています。
ボトルネックになるリソースが何かで分けた、という設計です。

もう1つは状態管理です。
単語ハイライト、字幕の自動スクロール、タイムラインの再生ヘッドという
3つの表示面を同期させる必要があったのですが、
『再生時刻を唯一の状態源にする』という方針を採って、
全部そこから導出する形にしました。
状態を2つ持つとズレのバグが出るので、構造的に排除した形です。

こうした設計判断は、ADR——Architecture Decision Record——として
6本文書化してリポジトリに置いています。
判断の理由と、却下した代替案も一緒に残しています。」
```

**なぜこれが強いか**：
- 「却下した代替案を語れる」= **考えた過程がある証拠**
- 「構造的に排除した」= 設計思考の言語
- **ADRという物証がある**（日本で5年働いてもADRを知らないエンジニアは多い）
- **全部お前が実際に書いたもの。深掘りされても崩れない**

# 🤖 Q6「これはAIを使って作りましたか」★2026年の新質問

**隠すな。正面から答える方が圧倒的に強い。**

```
「はい、実装には生成AIを積極的に使っています。

ただ、AIに任せているのは実装で、設計判断は自分でしています。

たとえば先ほどの『文字起こしは直列、ダウンロードは並列』という判断も、
『再生時刻を唯一の状態源にする』という判断も、
なぜそうしたのか、どの代替案を却下したのかをADRに残しています。

やってみて実感したのは、
AIを使うほど『何を作るか』『なぜそうするか』を
自分で決めて言語化する必要が出てくる、ということです。
指示が曖昧だと、動くけれど後で崩れるコードが出てくるので。

実務でもAIを前提とした開発になっていくと思いますので、
その使い方を個人開発で練習している、という位置づけです。」
```

**深掘り対策**：
- Q「じゃあ自分で書ける？」→ A「書けます。ただ速度が違うので、書くより設計とレビューに時間を使う方が結果が良いと考えています」
- Q「AIのコードを理解している？」→ A「理解していない部分を残さないようにしています。分からないコードが入ると、後で直せなくなるので」（※**これを言うならWeek 1-3の読解を必ずやれ。嘘になる**）

# 🎤 逆質問リスト（必ず用意しろ）

**「何か質問はありますか」で「特にありません」は志望度が低いと判定される。**
3〜5個用意して、状況に応じて2〜3個聞く。

### 評価が上がる質問（実務への関心を示す）
```
1. 「入社後、最初に担当することになる業務はどのようなものでしょうか」
2. 「チームの構成と開発の進め方を教えていただけますか。
    設計はどの粒度で、レビューはどのように行われていますか」
3. 「クラウド周りは専任のチームがあるのでしょうか、
    それとも開発メンバーが設計から構築まで担当する体制でしょうか」
   ← ★お前の志望動機と直結。必ず聞け
4. 「技術選定はどのように決まりますか。
    現場のエンジニアから提案する余地はありますか」
5. 「入社後、早期にキャッチアップすべき技術や知識があれば教えてください」
```

### 条件面の質問（最終面接 or オファー面談で）
```
6. 「資格取得の支援制度はありますか」← AWS資格を継続したいので実利がある
7. 「リモートワークの運用状況を教えていただけますか」
8. 「外国籍社員の方はいらっしゃいますか。
    在留資格の更新手続きなどのサポート体制について伺えますか」
```

### ❌ 聞くな（一次〜二次では）
- 給与・賞与の具体額（オファー面談で聞く）
- 残業時間・有給消化率を最初に聞く（条件しか見ていないと思われる）
- 「福利厚生を教えてください」（HPに書いてある）
- 調べれば分かること（**準備していないと即バレ**）
