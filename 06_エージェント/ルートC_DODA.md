# ルートC：DODA（猎头推薦＋自己検索）

> **対象**：DODA（doda.jp）
> **チャネルの性質**：**2つの入口がある** ①キャリアアドバイザー（CA）推薦 ②自分で検索
> **データ本体**：`DODA求人台帳.md`（このファイルは実行手順と最新状態のサマリ）
> **判定基準**：`求人スクリーニングプロンプト.md`（v3.2）＋`会社スクリーニング基準.md`（v3.1）

---

## 1. このルートの2つの入口（混同しない）

| 入口 | URL | 性質 | 判定のしかた |
|---|---|---|---|
| **① CA推薦求人** | `/recruits/referredJob/referredJobList/` | CAが選んで送ってくる。**受け身** | CA推薦は**量が多く玉石混交**。ルートAに近い足切り＋通常調査 |
| **② 自分で検索** | DODA の求人検索 | **能動的**。母数が無限 | 自分の条件で絞る。**ルートBに近い通常調査** |
| （参考）企業からのオファー | `/dcfront/bookmark/bookmarkCompany/` 等 | 企業が直接送る | **ほぼSES/派遣**（過去確認済み）。基本見送り |
| （参考）気になるした企業 | `/dcfront/bookmark/bookmarkCompany/` | 自分が保存した企業 | 見返し用。判定済みの会社が多い |

**重要**：DODAのCA推薦は「インフラ/AWS職が6割」など**CAの営業都合で偏る**。母数が大きいので、
**推薦に頼らず②の自己検索を主軸にする**のが正しい使い方。

---

## 2. 調査手順

### ① CA推薦を処理する場合
1. `referredJobList` の総件数を確認し、前回以降の**新規のみ**を抽出（社名＋年収で差分）
2. 足切り（ルートAの5基準に準拠）＋詳細ページ確認（v3.2）
3. 判定＋4層タグ

### ② 自己検索する場合（推奨）
1. DODA検索で以下の条件を設定する：
   - 職種：**アプリケーションエンジニア / サーバーサイド / クラウドエンジニア（開発寄り）**
   - エリア：東京・神奈川・千葉・埼玉
   - 年収：**400万以上**
   - キーワード：**Java / C# / AWS / 移行 / 自社開発 / 内製**
   - **除外**：運用保守・監視・ヘルプデスク・テストのみ
2. 出てきた企業を `DODA求人台帳.md` に追記し、通常調査
3. **「客先常駐」「派遣」「案件選択」の語で除外**（詳細ページで確認）
