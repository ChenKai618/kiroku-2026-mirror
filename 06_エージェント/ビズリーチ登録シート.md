### 順序

1. アカウント登録する
2. **レジュメを「非公開」のままにする**（初期状態から公開に切り替えない）
3. **企業ブロック設定**を探して、以下を登録する

4. ブロックが有効になっているのを確認する
5. **その後で**レジュメを記入し、公開に切り替える

> 設定の場所：「各種設定」→「公開設定」または「ブロック企業設定」付近。
> **名称はサービスによって違う。見つからなければサイト内ヘルプで「ブロック」を検索。**

登録するたびに、**必ず最初にブロック設定をする。**

### 🔴 「具体的な数字」について — 数字を作るな

公式は「数字**や**事実」と書いている。**事実でよい。**

入力例が売上数字（達成率140%・12名マネジメント）なのは営業職だからだ。
**エンジニアが数字を作ると面接で崩れる。**

この要約で使っている検証可能な具体情報：

| 記述 | 性質 |
|---|---|
| 12名体制 | 事実 |
| 約2ヶ月でCLF・SAA・SAP | 事実 |
| 約2年間 | 事実 |
| 大手SIer元請 | 事実 |

「処理速度を30%改善」のような数字を作れば、
面接の一問目が**「どう測定されましたか」**になる。そこで終わる。
→ [ADR-0003](../docs/adr/0003-no-factual-fabrication.md)

### この要約の3つの意図的な処理

**① 現職ではなく公的機関から書き起こす**
公式が「時系列で並べ」と指示している。加えて、
冒頭が「2年の経験がある人」になる。現職から始めると「来て5ヶ月の人」に見える。

**② 「部隊」「軍」を一字も書かない**
「公的機関」のみ。守秘義務の説明は面接で口頭で行う。
→ [ADR-0011](../docs/adr/0011-monitoring-project-backs-infra-tags.md)

**③ 顧客名を一字も書かない**
MS&AD／三井住友海上／NTTデータは一切出さない。

### 文字数超過時の削除順

```
1. 「業務外でも個人開発を継続し〜」        ← 最初に削る
2. 「単体テスト仕様書の作成と実施、移行前後の〜」
3. 「その後大学に編入し、卒業研究では〜」

★最後まで残す：
  ・「外部設計書・内部設計書を日本語で作成し、設計レビューを通過」
    → 在日中国人エンジニアとの差別化点
  ・「AWS認定資格をCLF・SAA・SAPまで約2ヶ月で取得」とその理由
    → 志望方向そのもの
  ・1行目の「損保・基幹システム・AWS移行・大手SIer元請」
```

### 🔴 【成果】欄について — ここで数字を作るな

ビズリーチ公式サンプルの【成果】欄は
「売り上げ□□億円」「受注率□□%増加」で埋まっている。
**それを見て数字を作りたくなるが、やってはいけない。**

**エンジニアの成果は売上ではなく成果物である。**
「設計書を作成しレビューを通した」「UTを実施した」「資格を取得した」——
これらは全て検証可能な事実であり、**面接で深掘りされても崩れない。**

一方、作った数字（「処理速度を30%改善」等）は
**面接官が必ず「どう測りましたか」と聞く。** そこで終わる。

> 💡 **【企業規模】は書かず【プロジェクト規模】にする。**

> SES・受託のエンジニアは**案件の規模を書くのが慣例**であり、
> 「大手SIer元請・12名体制」の方が情報量が多い。

### 🔴 この案件は「インフラ経験」として機能する（重要な発見）

職種欄で「インフラエンジニア」「サーバーエンジニア」を選ぶことに
**誠実性の懸念があった**（現場のAWSは基盤チームの担当のため）。
**この案件でその懸念は解消される。**

複数ホストのCPU・メモリ・ディスクを収集し、閾値超過でアラートを出す
——**これは監視・運用（Observability）そのものであり、
CloudWatch や Zabbix が担う領域と同じ**。

| 選択した職種タグ | このプロジェクトによる裏付け |
|---|---|
| **インフラエンジニア** | ✅ サーバー監視システムの設計・実装 |

| SE（Web・オープン系） | ✅ ASP.NET Core による REST API |

**つまりタグは事実に裏付けられている。** 面接で
「インフラの経験は？」と聞かれたら、こう答えられる：

```
「前職で、複数のサーバーホストを対象とした監視システムを開発しました。

### 🔴 絶対に書かない・言わないこと

| 項目 | 理由 |
|---|---|
| **「総線／バス」のデータが何か** | 軍用システムのデータバスは、書いた瞬間に用途（車両／艦船／航空）が推測される |

| **「部隊」「軍」という語を書面に書く** | 書面に残す必要がない。口頭で「国防関連の公的機関」と言えば足りる |
| 具体的な監視項目の閾値・台数 | 運用の実態が推測される |

**技術スタック（WPF・Prism・ASP.NET Core・EF Core）は一般技術であり、記載して問題ない。**
**CPU・メモリ・ディスクの監視も、あらゆる監視システムが行うことであり問題ない。**
**独自ルールは抽象化する** ——「システム間連携データの異常検知」「ファイル生成間隔の監視」。
**能力を語り、対象を語らない。**

## 現年収 → **300万円**（正直に書く）

**盛るな。** 理由は道徳ではなく実務：

- 入社時、**同一年内の転職なら前職の源泉徴収票の提出が必須**（年末調整のため）。
  そこに支払金額が書いてある
- 2024年の東京高裁判例（令和6年12月17日）では、
  内定後の経歴調査で**短期職歴と空白期の隠蔽が発覚し、内定取消しが有効**とされた

### ✅ #2・#3 は事実に裏付けられている（懸念は解消済み）

**当初、インフラ系タグを選ぶことに誠実性の懸念があった**
（現場のAWSは基盤チームの担当であり、構築経験がないため）。

**2社目の案件で、この懸念は解消された。**

前職で開発した**サーバー監視・アラート通知システム**は、
複数ホストのCPU・メモリ・ディスクを収集して可視化し、
閾値超過でアラートを出すもの ——
**これは監視・運用（Observability）そのもので、
CloudWatch や Zabbix が担う領域と同じである。**

| タグ | 裏付け |
|---|---|
| インフラエンジニア | サーバー監視システムの設計・実装（2019-2021） |
| サーバーエンジニア（構築・運用） | 複数ホストの稼働監視・障害検知 |

**ただし、守る線は変わらない。** 面接で聞かれたら正直に言う：

```
「前職で複数サーバーの監視システムを開発しました。
CPU・メモリ・ディスクを収集して可視化し、
閾値超過でアラートを出す仕組みです。

ただ、サーバーそのものの構築・運用ではなく、
監視する側のシステムを作る立場でした。

現在の案件のAWS側は基盤チームの担当で、私は開発側です。
構築の実務はこれからですが、
監視・運用の観点は前職で身についていると考えています。」
```

**「作った側であって運用した側ではない」を自分から言う。**
弱点を先に認めれば、その攻撃は成立しない（[ADR-0006](../docs/adr/0006-ai-assisted-development-disclosure.md)）。

### 後半：能力の記述（★公式サンプルの本当の型）

公式サンプルの6行を分解すると、規則が見える：

これは防弾チョッキだ。この語がないと

### 並び順の理由

| 位置 | 役割 |
|---|---|
| 前半（検索キーワード） | **見つけてもらう**ため。これがないと検索結果に出ない |

| 後半（能力の記述） | **見つけてもらった後に効く**部分。記憶に残る |

**検索に効く語を先に、記憶に残る語を後に。**

### 🔴 確認してから入れるもの（推測で入れるな）

| キーワード | 確認すること |
|---|---|

### ⚠️ 大阪を選ぶ場合の実務上の注意

**① 9月は現地面接に行けない**（有給が10/1発生のため。全日休むと最も目立つ）
→ **一次面接はオンラインを希望する**。「オンラインでも可能でしょうか」は関西企業への
　 遠方候補者からの依頼として全く普通。**最終面接だけ現地に行く**（その頃は有給がある）
→ 関西行きは**2〜3社まとめて1日で回る**。新幹線代（往復約2.8万円）は一度で済ませる

**② 入社日を12月1日に固定しない**
12月に「入社・引越し・各種届出・在留期間更新申請」が全部重なる。
**12月中旬または1月1日入社**の交渉は完全に合理的で、日本企業も理解する。
**引越し費用補助の有無は面接で聞いてよい**（正当な質問）。

**③ 転居後は住居地の届出が14日以内に必要**（入管法）。
また在留手続の管轄が**大阪出入国在留管理局**に変わる。資格自体には影響しない。

## ⚠️ 現実的な期待値

**ビズリーチには入会審査があり、全体的に高年収層向けのサービスだ。**

現年収300万・在日6ヶ月という条件では、
**審査に通らない、または通ってもスカウトが少ない可能性がある。**

**それは失敗ではなく、情報だ。** そしてどちらの結果でも計画は変わらない：

- 審査に通った → **スカウトの提示額が市場価格の答え**。年収交渉の根拠になる
- 通らなかった／スカウトが少ない → **レバテックキャリアと総合大手に集中する**。
  この2社は審査の性質が違う

**ここで詰まっても粘るな。** 次の2社に進め。
