# 応募管理表（正式応募後のファネル主表・2026年9月5日改訂）

> 🔴 **この表を自分で管理しないと、重複応募で落ちる。**
> エージェント（猎头）は他社の動きを知らない。**2社が同じ会社に出すと通常その場で落選する。**
> 応募する前に必ずこの表＋各台账を横断検索しろ。

---

## 📌 記録のルール（台账との役割分担）

| 段階 | 記録先 |
|---|---|
| サイトで見つけた・判定した（✅/⚠️/❌） | **台账**（サイト別。入口） |
| サイトでエントリー操作をした | 台账の状態を「**応募依頼済**」に更新 |
| **猎头が処理して正式応募が成立** | **この表に1行追加**（ここからが主表） |
| 書類選考・面接・結果 | この表の状態列を更新（台账には書かない） |

**「応募」の定義**：サイト上で自分がボタンを押しただけでは応募にならない。
レバテック/DODA は猎头の処理を経て正式応募になる。**正式応募が成立した時点**で行を追加する。

---

## 🔄 ブラウザ同期（手入力ゼロの記録方法）

応募が溜まったら、**「同步」と言うだけで自動記録される**：

1. レバテック or DODA の「応募履歴」ページを開いておく（ログイン済みのブラウザ）
2. 「応募履歴を同期して」と伝える
3. AI がブラウザでページを読み、この表と差分を取り：
   - 無い行 → 追記（会社・経路・応募日・職種・状態）
   - ある行 → 状態だけ更新（書類待ち→書類通過→一次…）
4. 追記内容を確認してから確定する（勝手に書かない）

**手入力が必要なのは合否だけ**：選考結果はメール通知が多く、ページに載らない。
通過・落選はメールを貼るか一言伝える → AI が1行更新する。

**タイミング**：応募した日の夜5分。無理なら週2回でよい。**絶対に毎日は不要。**

## 🏢 会社カテゴリの調べ方（在留資格更新に直結）

応募前に必ず調べろ。**これが入社後の手続きの重さを決める。**

| カテゴリ | 判定方法 |
|---|---|
| **1** | **上場しているか** → 会社名 + 「IR」or「株主」で検索。証券コードがあれば上場 |
| **2** | 従業員数の目安：**数百人以上**なら該当する可能性が高い（前年源泉徴収税額1000万円以上） |
| 3 | 中小企業（従業員数十人〜） |
| 4 | 設立直後・零細 |

**確認の質問（面接やオファー面談で聞いていい）**：
```
「在留資格の更新申請の際、
御社は所属機関のカテゴリーでいうと
どちらに該当されますでしょうか。
提出書類の準備の参考にさせていただきたく。」
```
> 人事担当者なら答えられる。答えられない会社は外国人雇用の経験が薄い。

## 🎯 応募の配分（v3・クラウド接触度ソート）

- 応募先は**台账の ✅判定**から選ぶ（`会社スクリーニング基準.md` v3・6章）
- 第一波は **10〜15社**。クラウド接触度（高/中/低）と採用可能性で並べる
- **偏りチェック**：全部が同じ業態・同じ年収帯になっていないか確認する
- ❌ **応募しない**：SES・派遣・客先常駐・カテゴリー4の零細企業（現段階）

### オファー判断ライン（2026/9/5固定・住居コスト込み）
```
400万以上   → 受諾検討（正社員・カテゴリー1/2が前提）
370〜400万  → 交渉必須。上流工程＋クラウド接触度が高い環境なら受諾も検討
350万前後   → 原則辞退。社宅(2.5万)→民間賃貸(5-8万)の差分で実質横ばい
350万未満   → 断る。契約更新 or 満了退社の方が正しい
```
