# 卒業研究のWeb開発を「その他の開発経験」として明示し、技術線の断絶を解消する

本人から「職歴はC#/WPFとJavaなのに、個人開発はReact/TypeScript。割裂している」という
指摘があった。**この割裂は実在しない。書き漏らしていた。**

GitHubの調査で判明した事実：

```
Novel / Novel-e              C# 101K〜129K + Dockerfile   2024年2月〜4月
Novel-master / -main         TypeScript 414K〜429K        2024年2月〜4月
epub-reader / react-neat-reader / netflix-clone / prompptopia   React・TS   2023年
```

`Novel`（C#バックエンド）と `Novel-master`（TypeScriptフロントエンド）は
**時期が完全に重なり、命名も対になっている＝一つのシステムの前後半**。
本人は2024年の卒業研究で、**フロントエンド分離型のWebアプリケーションを一人で実装している。**
さらに2023年からReact/TypeScriptの開発を継続している。

したがって技術線は本来こう繋がっている：

```
C#/WPF（2019-21） → C# API + React SPA（2024・卒業研究） → Java（2026・現職）
                  ↘ React/TypeScript 個人開発（2023〜現在）
```

## 「職歴」ではなく「その他の開発経験」に書く

雇用関係ではないため、職歴欄には書かない。
「その他の開発経験」「学生時代の開発経験」欄に記載する。

職歴として書けば [ADR-0003](./0003-no-factual-fabrication.md) の
事実欄不可侵の線を越える —— 入社2ヶ月後に、この職歴を
在留期間更新許可申請書に転記することになるためである。

**正しい欄に書けば加点は一切減らず、リスクはゼロになる。**

## 却下した選択肢

**Web系の職歴を1段追加する**：本人が最初に検討した方向。
だが雇用実体がないため事実欄の改変にあたり、ADR-0003 の射程に入る。
そして**そもそも不要**だった —— 真正な材料が既に存在していたため。

**割裂を放置する**：Web系ポジション（応募先の一部）への説得力を失う。
また面接で「なぜ急にWeb系の個人開発を？」と問われたときに、
「学生時代から継続している」という最も自然な答えを使えなくなる。

## 併せて実施した変更

- スキル欄の並び順を変更：TypeScript・React を前方へ、Docker を追加、Linux を削除
  （応募先にWeb系が含まれるため。またDockerは卒業研究で使用した事実がある）
- 職務要約に2023年以降のWeb開発継続と卒業研究の分離構成実装を追記
- 「活かせる経験・スキル」に**フロントエンド／バックエンド双方の実装経験**を追加
  （片側しか経験のないエンジニアが多い日本市場では差別化要素になる）
