# AI利用は隠さず、自分から開示する

個人開発プロジェクトの実装は大半が生成AIによるものであり、
コミットもAIが行っている。**この事実を面接で隠さない。**
「AIで作ったのか」と問われる前に、自分から「実装にはAIを使っている」と述べる。

## 判断の根拠

**隠せば嘘になり、嘘は深掘りで崩れる。**
2026年時点で日本の面接官もAI生成ポートフォリオへの警戒を持ち始めており、
「このコードで一番苦労した点は」「なぜこの設計にしたのか」という
標準的な深掘り質問は、そのまま検出装置として機能する。

一方、先に開示すれば：

- 後から矛盾しない
- 「AIを使うほど設計判断の言語化が必要になる」という主張に転換できる
  （これは2026年の実務認識として正しい）
- ADRという物証で裏付けられる（[ADR-0005](./0005-portfolio-as-design-evidence.md)）
- 「実務でもAI前提の開発になる」という将来の働き方の議論に接続できる

## 同じ原則を他の弱点にも適用する

- **AWS実務経験**：SAPを保有しながら「AWSは得意です」と述べると、
  面接官は必ず実務の深さを試しに来る。
  **先に「実務経験はまだ浅い」と自分で述べれば、その攻撃は成立しない。**
- **設計の役割**：「主導した」とは書かない。「参加した」と書く
- **AWS構築**：「基盤チームの担当で、自分は開発側。構築経験はない」と正直に述べる

## この原則が解決する、より大きな問題

本人は「入社後に能力不足が露呈するのではないか」という不安を抱えている。

**インポスター症候群の解毒剤は、詐称しないことである。**

本プロジェクトの資料には虚偽が存在しない（[ADR-0003](./0003-no-factual-fabrication.md)）。
AI利用は開示し、AWS実務の浅さは自己申告し、経歴は事実のみ。
したがって**「露呈すべき嘘」がそもそも存在しない。**

企業がそれらを知った上で採用を決めるなら、それは企業の判断である。
面接官・技術責任者・試用期間という評価の仕組みは企業側が持っており、
**候補者が企業に代わって自分を不採用にする必要はない。**

## 未解決として残す項目

**AIなしでコードを書けるかは未知数である。** 「できない」でも「大丈夫」でもなく、
**測定していない**というのが正確な状態。
コミット数はAIの実装を含むため、この能力の証拠にはならない。

3週間の無AI訓練（`04_コード理解/コーディング力への不安.md`）の
第3週で、自分のリポジトリに手動で機能を追加することにより測定する。
**「たぶん大丈夫」で埋めない。**
