# ポートフォリオは「実装力の証明」ではなく「設計判断の証拠」として使う

個人開発4プロジェクトのうち、`bikuri-NihongoLens` を主軸に据える。
理由は技術的な深さではなく、**`docs/adr/` に設計判断が6本記録されている**ことにある。

面接での提示物は、コードそのものではなく
「決定・理由・却下した代替案・残る制約」の4点構造とする。

## なぜこの位置づけなのか

実装はAIが行っており、**本人がAIなしでコードを書けるかは未検証**である
（[ADR-0006](./0006-ai-assisted-development-disclosure.md)）。
したがってポートフォリオを「実装力の証明」として提示すると、
深掘りされた瞬間に崩れる。**未検証の能力を証拠として出してはいけない。**

一方、ADRに記録された設計判断は本人が下したものである
（ADR-0006 に「grilling 討論による」と明記されており、
プロジェクト設計時に対話を通じて判断を固めた記録が残っている）。
「なぜGPUが1枚だから転録は直列なのか」「なぜ再生時刻を唯一の状態源にしたのか」
「どの代替案をなぜ却下したのか」——**これらは本人の判断であり、深掘りに耐える。**

そして日本のIT中途採用において、**ADRを書く習慣を持つ候補者は稀である。**
実装力で競合すれば埋もれるが、設計判断の言語化で競合すれば際立つ。

## 面接準備の帰結

準備の目的は「学習」ではなく「想起」となる。
ゼロから理解するのではなく、**自分が過去に下した判断を読み返して日本語で言語化する**作業。
これは1〜2週間で完了する。

## 却下した選択肢

**`aws-mondai` を主軸にする**：75コミット・稼働中・実利用者ありで実績としては最も強いが、
問題データがExamTopics由来のため非公開とする判断を本人が下している。
面接では画面共有によるデモに留め、リポジトリURLは提示しない。
**「出典の扱いを整理できていないため公開を保留している」という説明は、
むしろ著作権への意識を示す加点材料になる。**

**ポートフォリオを提示しない**：
実装力に不安があるなら触れない、という選択もありうる。
だが**設計判断の証拠を捨てることになり、本人の最大の差別化要因を失う。**
