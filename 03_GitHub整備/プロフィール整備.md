### プロフィールREADMEを刷新

**変更前の問題点**：
- 「目前在日本当社畜」← **自嘲。日本の採用側が見ると印象が悪い**
- **中国語で書かれていた** ← 日本の採用担当は読めない
- 内容がサイクリング・ランニング中心で、**技術的な情報がゼロ**
- 「Chiba / Tokyo」← 職務経歴書の記載と揃っていない

**変更後の構成**：

| セクション | 意図 |
|---|---|
| **ヘッダー** | 名前・職種・所在地の直後に**AWS SAP/SAA/CLF と JLPT N1 のバッジ**。資格は視覚的に出す方が速い |
| **現在** | **「損害保険会社向け基幹システムの オンプレミス → AWS 移行案件（大手SIer元請 / 12名体制）」を最初のスクロールに置く**。ここで手が止まる |
| **Tech Stack** | Backend / Frontend / Infrastructure に分けたバッジ。**羅列より分類の方が「整理できる人」に見える** |
| **個人開発** | ★核心。**ADR-0002 と ADR-0004 の中身を要約して直接リンク**している |
| **経歴** | 表形式。2019-2021の監視システムを技術スタック付きで |
| **言語** | 日本語N1を「業務における設計書作成・会議・報告」と具体化 |

**設計上の判断**：
- **GitHub Stats カードを入れなかった** — 公開インスタンスが 503 を返し不安定。
  **壊れた画像がプロフィールに残る方が、統計がない方より悪い**
- **草（contribution graph）を強調しない** — 実装の多くはAI併用であり、
  コミット数を実装力の証拠として提示しない（[ADR-0006](../docs/adr/0006-ai-assisted-development-disclosure.md)）
- **ADRの中身をプロフィールに書いた** — リンクだけでは踏まれない。
  「GPUが1枚だから直列」「再生時刻を唯一の状態源に」という**判断の内容そのもの**を見せる

### 🎯 このプロフィールが面接で機能する仕組み

面接官が「個人開発について教えてください」と聞く前に、
**プロフィールを見た時点で以下が伝わっている**：

1. 金融系基幹システムのクラウド移行に従事している（＝業務の格）
2. AWS SAP を持っている（＝保有者が少ない）
3. **ADRを書く**（＝日本で5年働いても知らないエンジニアが多い習慣）
4. 却下した代替案と「コードから読めない制約」を残している（＝設計者の視点）

**3と4がこのプロフィールの主武器。**
実装力ではなく設計判断で差別化する構造にしてある
（[ADR-0005](../docs/adr/0005-portfolio-as-design-evidence.md)）。

## 4️⃣ aws-mondai をどうするか（お前の判断：非公開のまま）

**了解。非公開のままで問題ない。** 代わりにこう扱う：

| 場面 | どうするか |
|---|---|
| 職務経歴書 | プロジェクト概要と技術スタックを記載。**リポジトリURLは載せない** |
| 面接で聞かれたら | 「ソースは非公開ですが、よろしければ画面共有でデモをお見せします」 |
| なぜ非公開か聞かれたら | 「問題データの出典の扱いを整理できていないため、公開は保留しています」 |

**この答え方は加点になる。** 「著作権やデータの出典を気にする人」に見えるからだ。
むしろ無防備に公開している方がリスクだった。

> 💡 将来公開する場合は、ExamTopics由来の問題データを除いて
> 「アプリケーションのコードのみ」を公開する形にすればクリーンになる。
