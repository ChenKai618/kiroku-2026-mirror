## 1️⃣ プロフィールREADME（`RainYaya/RainYaya` リポジトリ）

お前は既に `RainYaya` という自分用リポジトリを持っている。ここに `README.md` を置くと、
**GitHubのプロフィールページの一番上に表示される。**

以下をコピーして使え：

```markdown
# 陳凱 / Chen Kai

東京在住のソフトウェアエンジニア。金融系基幹システムのクラウド移行案件に従事しています。
個人開発では、日本語学習を支援するツールを中心に作っています。

## 現在

- 損害保険会社向け基幹システムの AWS 移行案件（外部設計・内部設計・UT）
- Java / Thymeleaf / AWS EC2

## 個人開発

| プロジェクト | 概要 | 技術 |
|---|---|---|
| [Kotoba Studio](https://github.com/RainYaya/bikuri-NihongoLens) | 日本語動画に単語レベルの字幕を生成する精読ツール | Python / FastAPI / WhisperX / React 19 |
| [baku-yomi](https://github.com/RainYaya/baku-yomi) | 日中対訳EPUBで逆翻訳を練習する語学アプリ | TypeScript / React / Edge TTS |
| [複合動詞図鑑](https://github.com/RainYaya/bikuri-goizukan) | 日本語複合動詞の組み合わせ可視化 | React / Vite |

設計判断は ADR（Architecture Decision Record）として残すようにしています。
→ [Kotoba Studio の ADR](https://github.com/RainYaya/bikuri-NihongoLens/tree/main/docs/adr)

## 資格

- AWS Certified Solutions Architect – Professional (SAP-C02)
- AWS Certified Solutions Architect – Associate (SAA-C03)
- AWS Certified Cloud Practitioner (CLF-C02)
- 日本語能力試験 N1

## 言語

日本語（N1・業務レベル） / 中国語（母語） / 英語（技術文書の読解）
```

**作り方**：
```bash
gh repo view RainYaya/RainYaya  # 存在確認
# ローカルにクローンして README.md を作成、push
```

> ⚠️ **メールアドレスや電話番号は書かない。** スカウトはGitHub経由では来ない。

## 2️⃣ 主力3リポジトリのREADME改善

### 共通してやること

**① 冒頭にスクリーンショットを入れる**

`bikuri-NihongoLens` の README には既に
`<!-- TODO: add screenshot here -->` というコメントがある。**そこを埋めろ。**

```bash
# スクショを撮って docs/ に置く
mkdir -p docs
# → docs/screenshot.png として保存
```

```markdown
# Kotoba Studio

![Kotoba Studio](docs/screenshot.png)

単人・本機・本地優先の日本語学習ツール。
```

**画像1枚は、テキスト100行に勝つ。** 面接官は読まずに見る。

**② デモURLを冒頭に明記**

```markdown
🔗 **[デモを見る](https://bikuri-goizukan.vercel.app)**
```

対象：
- `bikuri-goizukan` → https://bikuri-goizukan.vercel.app
- `Tokiwake` → https://tokiwake.vercel.app（※privateのままでOK）

**③ baku-yomi の README のバグを直す**

現在の clone 手順にプレースホルダが残っている：

```bash
git clone https://github.com/YOUR_USERNAME/baku-yomi.git   # ← ここ
```

→ `RainYaya` に修正する。

**細部の甘さは「詰めが甘い人」の印象を作る。** 20秒で直る。

## 3️⃣ Pin の設定（手動・ブラウザ）

APIから設定できないので手動。

1. https://github.com/RainYaya を開く
2. リポジトリ一覧の右上「**Customize your pins**」
3. 以下3つをチェック：
   - ☑ `bikuri-NihongoLens`
   - ☑ `baku-yomi`
   - ☑ `bikuri-goizukan`
4. Save

**この3つが第一画面に来ることが、GitHub整備の全目的だ。**

## 4️⃣ aws-mondai をどうするか（お前の判断：非公開のまま）

**了解。非公開のままで問題ない。** 代わりにこう扱う：

| 場面 | どうするか |
|---|---|
| 職務経歴書 | プロジェクト概要と技術スタックを記載。**リポジトリURLは載せない** |
| 面接で聞かれたら | 「ソースは非公開ですが、よろしければ画面共有でデモをお見せします」 |
| なぜ非公開か聞かれたら | 「問題データの出典の扱いを整理できていないため、公開は保留しています」 |

**この答え方は加点になる。** 「著作権やデータの出典を気にする人」に見えるからだ。
むしろ無防備に公開している方がリスクだった。

> 💡 将来公開する場合は、ExamTopics由来の問題データを除いて
> 「アプリケーションのコードのみ」を公開する形にすればクリーンになる。
