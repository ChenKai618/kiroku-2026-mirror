# baku-yomi AWS 迁移盘点

> 2026-08-30 初版 | 基于 clone 的当前代码（React 19 + Hono + Vercel AI SDK + Docker）
> 目的：转职弹药（职历书实操经验 + 面试谈资），效率打法：跑通为主、深挖为辅、排错必真实

---

## 一、项目现状画像（迁移前必须搞清楚的事）

| 维度 | 现状 | 对迁移的影响 |
|---|---|---|
| 架构 | **单体**：Hono 后端同时 serve 前端静态文件（dist/）+ SPA fallback | 必须拆分：前端→S3/CloudFront，后端→纯 API。这本身就是简历亮点「モノリス→分離」 |
| 状态 | **无状态、无数据库**（书签高亮在浏览器 localStorage） | 天大利好。Fargate 随便缩，天然适合 Serverless |
| AI Key | **BYOK**：key 由浏览器在请求里传来，后端不存储 | 不需要 Secrets Manager 存 AI key（省一大块）。后端只是代理 |
| TTS | Microsoft Edge TTS（免费无配置）/ VOICEVOX（可选，独立容器） | VOICEVOX 迁移时砍掉（它要单独引擎，AWS 上跑不划算）。Microsoft TTS 够用 |
| TTS 缓存 | 内存缓存 120MB（`TTS_CACHE_MAX_BYTES`） | Fargate 单容器 OK；部署/重启会丢，重新生成即可。面试可讲「缓存是无状态的，丢了只是回源」 |
| 端口 | 3003，`/health` 健康检查已内置 | Fargate 健康检查直接用 `/health`，省事 |

## 二、目标 AWS 架构（第一版：Fargate，稳）

```
                    Internet
                       │
                   [Route 53]  ← 没有域名可以先跳过，用 CloudFront 默认域名
                       │
                [CloudFront CDN]
                 │            │
        /api/*（后端）      /*（前端）
                 │            │
        [API Gateway]    [S3 bucket]
              │           （React 静态文件）
        [ALB]               SPA 404→/index.html 定制错误页
              │
         [ECS Fargate]
        （Hono 纯 API 容器）
              │
   ┌──────────┴──────────┐
[AI providers]    [Microsoft TTS]
（key 来自浏览器请求）
```

CI/CD（GitHub Actions）：
`push main → 构建前端 → S3 sync + CloudFront invalidation → 构建后端镜像 → ECR → ECS 滚动更新`

## 三、需要改的代码点（就 3 个，都很小）

1. **server/index.ts**：生产模式不再 serveStatic（前端已由 S3 托管）。
   加个开关：`const serveFrontend = process.env.SERVE_FRONTEND === 'true'`，默认关。改动 10 行内。
2. **CORS_ORIGIN**：设为 CloudFront 域名（如 `https://dxxxx.cloudfront.net`）。
3. **Dockerfile**：可不动（build 阶段照样出 dist，只是不再被 serve）。生产镜像可加 `SERVE_FRONTEND=false`。

## 四、第一步手动跑通顺序（控制台，约 2 个晚上）

1. **S3 + CloudFront 托管前端**：`pnpm build` 后把 dist/ 上传 S3（静态网站托管开，或只用 OAC + CloudFront）。
   - 坑预警：SPA 路由刷新 404 → CloudFront 定制错误响应 404→/index.html 状态码 200。
2. **ECR + ECS Fargate 跑后端**：构建镜像 push ECR，建任务定义（port 3003，env: NODE_ENV/CORS_ORIGIN/TTS_DEFAULT_PROVIDER），安全组只放行 ALB→任务，健康检查 /health。
   - 坑预警：前端调 API 超时 → 查安全组入站 + 子网路由。经典面试故事。
3. **打通前后端**：前端请求 `/api/*`，CORS_ORIGIN 指到 CloudFront 域名。

## 五、第二阶段（跑通后，按时间弹性做）

- **GitHub Actions**：`aws-actions/configure-aws-credentials`（用 **OIDC**，不用 AK/SK——这句面试必说）+ S3 sync + ECR push + ECS deploy（`aws ecs update-service --force-new-deployment`）。
- **AWS CDK（TS）**：把 S3/CloudFront/ECS 代码化。注意：CDK 正好是 TS，和你的主线技术栈一致，一箭双雕。
- **Lambda 化进阶**（时间富余再做）：Hono 有官方 `@hono/aws-lambda` 适配器。坑：TTS 返回二进制音频，API Gateway 要配 binaryMediaTypes。这是加分局，不是必需品。

## 六、面试弹药映射（每个组件 = 一句面试话术）

| 组件 | 能证明什么 | 面试官会追问 |
|---|---|---|
| S3 + CloudFront | 静态托管、CDN、边缘缓存 | 为什么 CloudFront？SPA 404 怎么处理的？OAC 是什么？ |
| ECS Fargate | 容器编排、Serverless 计算 | 为什么 Fargate 不 EC2？任务定义怎么配的？怎么滚动更新？ |
| OIDC + GitHub Actions | 现代 DevOps、安全实践 | 为什么 OIDC 不用 Access Key？最小权限原则怎么落的？ |
| 无状态设计 | 架构意识 | 缓存丢了怎么办？怎么水平扩展？ |
| BYOK 架构 | 安全设计 | 为什么不在后端存 key？CORS 怎么限制的？ |

## 八、明确不做的事（防止陷入完美主义）

- ❌ 不搞 Route 53 自定义域名（省钱省时间，CloudFront 默认域名够用，以后要加再说）
- ❌ 不搞 VOICEVOX 上云
- ❌ 第一版不搞 Lambda 化（留作进阶，Fargate 先跑通）
- ❌ 不追求高可用多 AZ 双容器（单容器先跑通，面试能解释为什么正式环境要多 AZ 即可）
